# ทดสอบ Shop บน Windows หนึ่งเครื่องและเครื่องลูกอีกสองเครื่อง

ชุดนี้ทดสอบแอปปัจจุบันด้วย SQLite ที่เก็บบนเครื่องหลัก ไม่ใช่ PostgreSQL และไม่ใช่ตัวติดตั้งจริง ไม่ใช้ข้อมูลธุรกิจหรือแชร์ไฟล์ฐานข้อมูลผ่านเครือข่าย

## จัดสามเครื่อง

| เครื่อง | หน้าที่ | ต้องติดตั้ง |
| --- | --- | --- |
| 1 เครื่องหลัก | รันเว็บ Shop และฐานข้อมูลทดสอบ ดูผลในฐานะผู้บริหาร | Node.js 24 LTS, โค้ด Shop ล่าสุด และ dependencies |
| 2 หน้าร้าน | เปิดเว็บและลงทะเบียนจุดขาย 1 | Edge/Chrome และเครื่องสแกน USB ถ้ามี |
| 3 ออฟฟิศ | เปิดเว็บรับเข้า/รายงาน หรือสลับมาจุดขาย 2 เพื่อทดสอบขายพร้อมกัน | Edge/Chrome |

เครื่องหลักต้องเปิดอยู่ เครื่องลูกไม่ต้องติดตั้ง Node.js, SQLite, PostgreSQL หรือ Docker ทั้งสามเครื่องเชื่อมเราเตอร์เดียวกัน ใช้ DHCP reservation ที่เราเตอร์เพื่อให้ IP เครื่องหลักคงเดิมได้

## เครื่องหลัก: ครั้งแรก

1. ดาวน์โหลด/checkout โค้ด main ล่าสุดในโฟลเดอร์ทดสอบแยก เช่น C:\Shop-LAN-Test ไม่ใช้โฟลเดอร์แอปที่กำลังทำธุรกิจ
2. ติดตั้ง Node.js 24 LTS จาก nodejs.org แล้วเปิด PowerShell ใหม่
3. เปิด PowerShell ในโฟลเดอร์โค้ด ใช้คำสั่งต่อไปนี้ (`.cmd` ช่วยหลีกเลี่ยงข้อจำกัด npm.ps1 โดยไม่ต้องลด Execution Policy):

```powershell
node --version
npm.cmd install --global pnpm@10.4.1
pnpm.cmd install --frozen-lockfile
pnpm.cmd build
pnpm.cmd test:lan --check
pnpm.cmd test:lan --prepare
pnpm.cmd test:lan
```

ไม่ต้องสร้าง .env หรือใส่ DATABASE_URL ชุดเริ่มทดสอบกำหนด SQLITE_DB_PATH และโฟลเดอร์สำรองไปที่ `.lan-test` ในโฟลเดอร์นี้เสมอ ไม่ใช้ค่าฐานข้อมูลธุรกิจที่อาจตั้งค้างใน Environment และไม่ seed บัญชี/ข้อมูลตัวอย่างอัตโนมัติ

- `.lan-test/store.sqlite` — ฐานข้อมูลทดสอบที่แอปสร้างเมื่อเริ่มใช้งาน
- `.lan-test/backups` — สำรองเฉพาะฐานทดสอบ
- `.lan-test/config.json` — พอร์ตและคีย์เซสชันเฉพาะชุดทดสอบ ไม่เผยแพร่หรือส่งไฟล์นี้ให้คนอื่น
- `.lan-test/https` — ใบรับรองเฉพาะชุดทดสอบเมื่อเปิด HTTPS

ไม่มีคำสั่ง reset/delete ในตัวเริ่มทดสอบ ปิดแล้วเปิดใหม่ข้อมูลยังอยู่ ถ้าพบฐานเดิมโดยไม่มีเครื่องหมายว่าเป็นชุดทดสอบ หรือพบพาธเชื่อมไปที่อื่น สคริปต์จะปฏิเสธการเปิด

เริ่มที่ `http://localhost:3001` สร้างผู้ดูแลด้วยรหัสผ่านของคุณเอง ตั้งชื่อร้านว่า **LAN TEST — ข้อมูลจำลอง** และเปลี่ยนรหัสผ่านเมื่อระบบร้องขอ ห้ามนำเข้าข้อมูลจริงในรอบนี้ สร้างผู้ใช้แยกสำหรับแต่ละเครื่อง/บทบาท อย่าใช้บัญชีเดียวกันพร้อมกันสามเครื่อง เพราะระบบมีการย้ายเซสชันเมื่อเข้าสู่ระบบด้วยบัญชีเดิม

## ให้สองเครื่องลูกเข้าเว็บ

ตัวเริ่มทดสอบแสดง URL ของเครื่องหลัก เช่น `http://192.168.1.10:3001` นำ URL ที่แสดงจริงไปเปิดใน Edge/Chrome ของอีกสองเครื่อง ค่า 192.168.1.10 เป็นเพียงตัวอย่าง

ถ้าเข้าไม่ได้:

1. ลอง localhost บนเครื่องหลักก่อน และตรวจว่า terminal ยังรันอยู่
2. ตรวจว่าสามเครื่องอยู่เครือข่ายเดียวกัน ไม่มี Guest Wi-Fi/client isolation
3. ตั้ง Network profile ของเครือข่ายร้านที่เชื่อถือได้เป็น Private
4. ให้ผู้ดูแล Windows เพิ่ม Firewall rule เฉพาะพอร์ตแอปและ LocalSubnet ตัวอย่างสำหรับพอร์ต 3001 เปิด PowerShell แบบ Administrator:

```powershell
New-NetFirewallRule -DisplayName "Shop LAN Test 3001" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 3001 -Profile Private -RemoteAddress LocalSubnet
```

ไม่ต้องเปิดพอร์ตฐานข้อมูล 5432 หรือแชร์โฟลเดอร์ SQLite ถ้าเลิกทดสอบสามารถลบเฉพาะ rule นี้ได้:

```powershell
Remove-NetFirewallRule -DisplayName "Shop LAN Test 3001"
```

ถ้าพอร์ตถูกใช้ ให้หยุดชุดอื่นหรือกำหนดพอร์ตว่าง เช่น `pnpm.cmd test:lan --port 3002` แล้วใช้พอร์ตเดียวกันใน URL และ Firewall ครั้งต่อไปสคริปต์จำพอร์ตไว้

ลงทะเบียนจุดขายบนแต่ละเบราว์เซอร์ที่จะชำระเงินจริงจำลองด้วยผู้บริหารทีละเครื่อง แล้วออกจากระบบและให้เจ้าหน้าที่แต่ละคนเข้าสู่ระบบด้วยบัญชีของตัวเอง จุดขายจำแยกตาม browser profile/origin การล้างข้อมูลเว็บ เปลี่ยน browser profile หรือเปลี่ยน http/https อาจต้องลงทะเบียนใหม่ ไม่ผูกด้วย IP/MAC

## ชุดทดสอบที่ควรทำร่วมกัน

ใช้ข้อมูลจำลองและบันทึกเลขบิล/ยอดก่อน-หลังเทียบกัน:

| งาน | ผลที่ควรได้ |
| --- | --- |
| เพิ่มสินค้า/สมาชิกที่เครื่องหลัก | อีกสองเครื่องโหลดหรือรีเฟรชแล้วพบรายการเดียวกัน |
| ขายสินค้าคงเหลือ 1 ชิ้นพร้อมกันสองจุด | สำเร็จได้หนึ่งบิล อีกเครื่องแจ้งสต็อกไม่พอ จำนวนไม่ติดลบ |
| สมาชิกมียอด 50 บาท ให้สองจุดลองหัก 40 บาทพร้อมกัน | สำเร็จหนึ่งรายการ เหลือ 10 บาท อีกจุดต้องไม่หักซ้ำ |
| รับเข้าสินค้าจากออฟฟิศ แล้วเปิดขาย | ยอดและราคาที่บันทึกปรากฏหลังโหลดข้อมูลใหม่ |
| ส่งยืนยันรายการเดิมซ้ำหลังการเชื่อมต่อสะดุด | ตรวจประวัติก่อนแก้บิล/เริ่มใหม่ รหัสเดิมต้องไม่สร้างเงินหรือสต็อกซ้ำ |
| ออกไปหน้าอื่นขณะจัดบิล | กลับมาพบบิลค้างใน runtime เดิม; ถ้าจะปิด/รีเฟรชให้ใช้พักบิลตามพฤติกรรมที่รองรับ |
| ยกเลิกบิลในรอบปัจจุบัน | คืนเงิน/สต็อกครั้งเดียว ยอดตัดรอบไม่รวมบิลยกเลิก |
| ยกเลิกบิลที่ปิดยอดแล้ว | ระบบปฏิเสธโดยไม่แก้เงินหรือสต็อก ยังไม่มี workflow คืนเงินข้ามรอบ |
| หยุดเครื่องหลักด้วย Ctrl+C แล้วเปิด `pnpm.cmd test:lan` ใหม่ | ข้อมูลและบัญชีทดสอบยังอยู่ ใช้ฐานเดิมต่อได้ |
| พิมพ์ฉลาก/ใบเสร็จ/รายงานจากแต่ละเครื่อง | เลือกเครื่องพิมพ์ของเครื่องนั้นและตรวจขนาดจริง |

## สำรองและลองกู้คืนโดยไม่ทับฐานที่รันอยู่

เปิด PowerShell อีกหน้าต่างในโฟลเดอร์โค้ด:

```powershell
pnpm.cmd test:lan --backup
```

นำชื่อไฟล์ที่ได้จริงแทน `ชื่อไฟล์จริง.sqlite` ด้านล่าง กู้คืนเป็นไฟล์พิสูจน์แยก ไม่ใส่ --overwrite:

```powershell
pnpm.cmd backup:sqlite:restore ".\.lan-test\backups\ชื่อไฟล์จริง.sqlite" ".\.lan-test\restore-check.sqlite"
pnpm.cmd backup:sqlite:verify ".\.lan-test\restore-check.sqlite"
```

ถ้า restore-check.sqlite มีอยู่แล้ว คำสั่งจะไม่ทับไฟล์ ให้ใช้ชื่อไฟล์พิสูจน์ใหม่ ไม่เปลี่ยนเป้าหมายไปเป็น store.sqlite หรือฐานธุรกิจ

## เครื่องสแกน กล้อง และฉลาก

เครื่องสแกน USB ที่พิมพ์รหัสแล้ว Enter ใช้กับ HTTP ได้ กล้องบนเครื่องลูกต้องใช้ secure context ถ้าจะทดสอบกล้องให้เลือก `pnpm.cmd test:lan --https` และจัดการ trust ใบรับรองบนเครื่องลูกตามนโยบายเครื่องนั้น การยอมผ่านคำเตือน self-signed อย่างเดียวอาจยังไม่ทำให้กล้องใช้ได้ในทุก browser เลือก scheme/IP/port ให้คงเดิมตลอดรอบทดสอบ

ในหน้า **สต็อกสินค้า → ฉลากสินค้า** เลือกสินค้า จำนวนใบ และขนาด พิมพ์ที่ 100% ปิดหัว/ท้ายกระดาษ แล้วลองสแกนใบแรกจริงก่อนจำนวนมาก:

- A4 ฉลาก 63 × 38 มม. สามคอลัมน์ เจ็ดแถว ระยะห่าง 2 มม. ขอบ 8 มม. ต้องตรงกับสติ๊กเกอร์ที่ใช้
- ม้วน 58 × 40 หรือ 80 × 40 มม. ต้องตั้งขนาดใน driver ให้ตรง ใช้หน้าต่างพิมพ์ของ browser
- มีบาร์โค้ดใช้รหัสเดิม ไม่มีใช้ SKU ไม่เขียนรหัสใหม่ ไม่เปลี่ยนสต็อก
- ฉลากเป็น Code128 ที่บรรจุรหัสเดิม เครื่องสแกนต้องเปิดอ่าน Code128
- รหัสไทย/ช่องว่าง รหัสซ้ำกับสินค้าอื่น หรือยาวเกินพื้นที่ จะไม่ให้พิมพ์จนแก้ปัญหาหรือเลือกขนาดที่เหมาะสม
- สินค้าขายตามช่วงราคาแสดงให้เลือกช่วงราคาที่ POS ไม่พิมพ์ราคาต่อหน่วยที่อาจทำให้เข้าใจผิด

ชุดนี้ยังไม่ใช่หลักฐานว่า PostgreSQL/Windows LAN/เครื่องพิมพ์จริงผ่านแล้ว ต้องทำ checklist บนสามเครื่องจริงต่อไป PostgreSQL ต้องเพิ่ม driver, schema/migrations และ repositories ทั้ง provider ก่อน ไม่เพียงเปลี่ยน DATABASE_URL และห้ามแยกครึ่งแอปเขียนคนละฐาน
