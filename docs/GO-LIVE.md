# คู่มือขึ้นระบบ ณ หน้างานลูกค้า (Go-Live Playbook)

สำหรับ **ช่าง/ผู้พัฒนา** ที่ออกไปติดตั้งระบบร้านค้าสวัสดิการให้ลูกค้า
ครบทุกขั้นตอน: เตรียมข้อมูลก่อนออกจากออฟฟิศ → ติดตั้ง → ตรวจรับ → ส่งมอบ

> ในแอปมีหน้า **ตั้งค่า → เครื่องมือติดตั้ง** (โซนผู้พัฒนา — บัญชี dev เท่านั้น)
> ที่รวมเครื่องมือทั้งหมดในคู่มือนี้ไว้ในหน้าเดียว: URL ร้าน ตรวจรับข้อมูล
> ทดสอบเครื่องพิมพ์ สำรองด่วน และเช็คลิสต์วันขึ้นระบบแบบติ๊กได้

---

## ภาพรวมบทบาท (แยกสิทธิ์ตั้งแต่ Round 56)

| บทบาท | เห็นอะไร | ใช้ทำอะไร |
|---|---|---|
| **เจ้าหน้าที่ (staff)** | POS · สต็อก · สมาชิก · รายงาน | ขายของหน้าร้าน |
| **ผู้บริหาร (admin)** — *ลูกค้า* | ทุกอย่าง + ตั้งค่าร้านค้า 9 แท็บ (แบรนด์/ใบเสร็จ/สมาชิก/ชำระเงิน/ตัดยอด/แสดงผล/แจ้งเตือน/สิทธิ์/Log) | ดูแลร้านประจำวัน |
| **ผู้พัฒนา (dev)** — *ช่าง* | ทุกอย่าง + **โซนผู้พัฒนา 4 แท็บ**: เครื่องมือติดตั้ง · นำเข้าข้อมูล · สำรองข้อมูล · การเชื่อมต่อ | ขึ้นระบบ/ดูแลระยะยาว |

หลักการ: **ข้อมูลลูกค้าเราเตรียมให้หมดก่อนวันติดตั้ง** — วันขึ้นระบบช่างแค่
นำเข้า ตั้งค่า ทดสอบ แล้วส่งมอบ ไม่ต้องนั่งพิมพ์ข้อมูลหน้างาน

---

## ขั้นที่ 0 — ก่อนออกจากออฟฟิศ (เตรียม 1-3 วันก่อน)

1. **รับข้อมูลจากลูกค้าให้ครบ** (ขอเป็น Excel/CSV):
   - รายชื่อสมาชิก + เลขสมาชิก + ยอดเงินคงเหลือ (+ วงเงิน/วัน ถ้ามี)
   - รายการสินค้า + บาร์โค้ด + ราคาขาย + ต้นทุน + จุดสั่งซื้อ
2. **เช็คไฟล์ให้สะอาด**: เปิดดูหัวตาราง ลบแถวว่าง/ตัวอักษรแปลก
   หรือใช้ปุ่ม **ดาวน์โหลดเทมเพลต .xlsx** ที่แท็บนำเข้าข้อมูล แล้วกรองลงไป
3. **เตรียมฮาร์ดแวร์ที่ลูกค้าซื้อ**: เครื่องพีซีขายหลัก, เครื่องพิมพ์สลิป
   (58/72/80 มม.), ปืนสแกน USB หรือใช้กล้องมือถือ/เว็บแคม, สายแลน/Wi-Fi
4. **เตรียมไฟล์ติดตั้ง**: clone โปรเจกต์ลง USB หรือ GitHub private
   (อนาคต: ไฟล์ .exe Tauri ไฟล์เดียว — ตามแผน)
5. **สร้างบัญชีช่างไว้ในเครื่องทดสอบ**: dev + รหัสแข็งแรง 12 ตัวขึ้นไปมีสัญลักษณ์

---

## ขั้นที่ 1 — ติดตั้งเครื่องเซิร์ฟเวอร์ ณ หน้างาน (≈30 นาที)

1. ติดตั้ง Node.js 22+ / pnpm / Git → โคลนโปรเจกต์ → `pnpm install`
   (รายละเอียดเต็ม: `docs/LOCAL-SETUP.md`)
2. ตั้งพอร์ตใน `.env`: `PORT=3001` (หรือพอร์ตที่ไอทีของลูกค้าอนุมัติ)
3. รัน: `pnpm dev` → เปิด `http://localhost:3001`
4. หน้าลงทะเบียนครั้งแรก (First-time Setup) ขึ้นมาเอง:
   สร้าง **บัญชีผู้บริหารหลักของลูกค้า** (ให้ลูกค้าพิมพ์รหัสเอง ช่างไม่ต้องรู้)

## ขั้นที่ 2 — เปิดประตูช่าง แล้วเข้าโซนผู้พัฒนา

1. ล็อกอินบัญชีผู้บริหาร → **ตั้งค่า → สิทธิ์และบทบาท** → เปิด Dev Access
2. **ผู้ใช้ระบบ** → สร้างบัญชี **dev** ของทีมเรา (รหัส 12+ ตัวมีสัญลักษณ์)
3. ออกจากระบบ → เข้าด้วยบัญชี dev → **ตั้งค่า → เครื่องมือติดตั้ง**
4. ทุกเครื่องมือที่เหลือของวันอยู่ในหน้านี้หน้าเดียว:
   - ข้อมูลเครื่อง + **LAN URL** (กดคัดลอก ส่งให้ทุกจุดขาย)
   - **ตรวจรับข้อมูล**: ตัวเลขบัญชี/สมาชิก/สินค้า/บิล — มีสินค้า ฿0 เด้งแดงเตือน
   - **ทดสอบเครื่องพิมพ์** + **สำรองด่วน**
   - **เช็คลิสต์วันขึ้นระบบ 10 ข้อ** (บางข้อระบบตรวจให้อัตโนมัติ)

## ขั้นที่ 3 — ขึ้นข้อมูลลูกค้า (≈15-45 นาที)

**นำเข้าสมาชิก** → แท็บนำเข้าข้อมูล (โซนผู้พัฒนา):
1. เลือก "สมาชิกและยอดเงิน" → อัปโหลดไฟล์ → ตรวจการจับคู่คอลัมน์
2. รายการซ้ำ: เลือก "ข้าม" (ปลอดภัยสุด)
3. ระบบ **สำรองข้อมูลกันไว้ก่อนนำเข้าทุกครั้ง** — พลาดกู้คืนได้ทันที

**นำเข้าสินค้า** → เลือก "สินค้าและสต็อก" → ขั้นตอนเดียวกัน
- หลังนำเข้า: เปิดหน้าสต็อก กรอง "ยังไม่ตั้งราคา" ให้ครบก่อนขายจริง

**ข้อมูลพรีเซ็ตที่ควรตั้งให้ลูกค้า** (แท็บตั้งค่าร้านค้า — admin ทำเองได้):
ชื่อร้าน/โลโก้ · ขนาดกระดาษสลิป · รอบตัดยอด · สี/สไตล์ที่ลูกค้าชอบ

## ขั้นที่ 4 — ต่ออุปกรณ์หน้าร้าน

| อุปกรณ์ | ต่อแบบไหน | ทดสอบยังไง |
|---|---|---|
| เครื่องพิมพ์สลิป | USB + ตั้งเป็นเครื่องพิมพ์เริ่มต้น | ปุ่ม "พิมพ์สลิปทดสอบ" ในแท็บเครื่องมือติดตั้ง |
| ปืนสแกน | USB (คีย์บอร์ดโหมด) | ชี้ช่องสแกน → ยิงบาร์โค้ดสินค้าจริง |
| แท็บเล็ต/มือถือจุดขายอื่น | เปิด LAN URL ในเบราว์เซอร์ → "ติดตั้งแอป" (Chrome/Edge) | ล็อกอินด้วยบัญชีเจ้าหน้าที่ของจุดนั้น |
| กล้องสแกนสำรอง | ปุ่มกล้องในช่องสแกน (ต้องเข้าผ่าน localhost หรือ HTTPS) | สแกนบาร์โค้ดจากจอ/ของจริง |

> **ถ้าจุดขายอื่นต้องใช้กล้องสแกน:** เพิ่ม `HTTPS=1` ใน `.env` ของเครื่องเซิร์ฟเวอร์แล้วรีสตาร์ท
> (ระบบสร้างใบรับรองให้เอง) — อุปกรณ์เข้าด้วย `https://IP:พอร์ต` กดผ่านหน้าเตือนครั้งแรกครั้งเดียว
> วิธีเต็ม: `docs/LOCAL-SETUP.md` → "เปิดกล้องสแกนบาร์โค้ดบนแท็บเล็ต/มือถือ (HTTPS)"

## ขั้นที่ 5 — ทดสอบขายจริง (ทำพร้อมลูกค้า ให้เห็นกับตา)

ทดสอบครบ 3 วิธีชำระ ทุกครั้งมีหน้า **ยืนยันก่อนบันทึกบิล**:
1. เงินสด — รับ ฿100 ทอนให้ถูก
2. QR — สแกนจริงด้วยโทรศัพท์
3. หักบัญชีสมาชิก — ใช้สมาชิกที่นำเข้ามา ดูยอดหักถูก
4. เช็คสลิปที่ออกมา: ไทยชัด · ชื่อร้านถูก · ยอดถูก · กระดาษตรงขนาด
5. ลอง **พักบิล (F5)** · **รายการพิเศษ/ของสั่ง (F4)** · **เติม-ถอนเงิน (F2/F3)** · **สมาชิกใหม่ + พิมพ์บัตร (F6)**

## ขั้นที่ 6 — ส่งมอบ (Handover)

1. **เปลี่ยนรหัสผู้บริหาร** ให้ลูกค้าพิมพ์เอง (ช่างไม่รู้รหัสลูกค้า)
2. **ตั้งสำรองอัตโนมัติ** (ทุก 24 ชม. + ดาวน์โหลด 1 ชุดเก็บ USB/คลาวด์)
3. **ปิด Dev Access** ที่แท็บสิทธิ์และบทบาท → บัญชีช่างเข้าไม่ได้จนลูกค้าเปิดใหม่
   (ลูกค้ากลับมาใช้บริการ → โทรให้เปิดประตู แล้วช่างเข้าได้ทันที)
4. สรุปวิธีใช้หลัก 15 นาที: ขาย · เติม/ถอน · สมาชิกใหม่ · รายงานประจำวัน · สำรองข้อมูล
5. ทิ้งข้อมูลติดต่อ + คู่มือฉบับย่อ `docs/LOCAL-SETUP.md` ให้ทีมร้าน

## ปัญหาที่เจอบ่อย ณ หน้างาน

| อาการ | สาเหตุ/วิธีแก้ |
|---|---|
| เครื่องอื่นเปิด URL ไม่ได้ | เช็ค Wi-Fi/แลนเดียวกัน · ไฟร์วอลล์ Windows ปล่อยพอร์ต · ดู IP ล่าสุดที่แท็บเครื่องมือติดตั้ง |
| กล้องสแกนเปิดไม่ได้ | เบราว์เซอร์เปิดกล้องได้เฉพาะ localhost/HTTPS — ใช้ปืนสแกน หรือเปิดที่เครื่องเซิร์ฟเวอร์ หรือเปิด `HTTPS=1` ใน `.env` แล้วให้อุปกรณ์เข้าด้วย https:// (ดูคู่มือ LOCAL-SETUP.md) |
| พิมพ์แล้วไม่ออก | เครื่องพิมพ์เริ่มต้นผิดตัว · กระดาษ/หมึก · ลองสลิปทดสอบก่อนเสมอ |
| ไทยพิมพ์เพี้ยน | เลือกขนาดกระดาษผิด (58/72/80) หรือดรไอเวอร์ฟอนต์ — ตั้งที่แท็บใบเสร็จ |
| นำเข้าแล้วตัวเลขไม่ตรง | ดูผลการนำเข้า (เพิ่ม/อัปเดต/ข้าม/ผิดพลาด) — ไฟล์ป้องกันก่อนนำเข้าอยู่ที่แท็บสำรองข้อมูล |
