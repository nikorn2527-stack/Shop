# ขึ้น Railway ใช้งานจริงก่อน (Cloud Server) — ฉบับ 10 นาที

> เหมาะกับสถานการณ์ตอนนี้: **ไฟบ้านดับ / ยังไม่อยากพึ่งเครื่องบ้าน** — ขึ้นคลาวด์แล้วได้ลิงค์ถาวรใช้ได้ทันทีจากทุกที่ (มือถือ / หน้าร้าน / ส่งให้คนอื่นดู)
>
> **Workflow ของทีม:** `dev` = ห้องพัฒนา · `main` = ตัว deploy — **deploy จาก branch `main`** (merge จาก dev เมื่อทดสอบแล้ว)
>
> สิ่งที่ได้: ลิงค์ `https://ชื่อโปรเจกต์-xxxx.up.railway.app` (คงที่ ไม่เปลี่ยน) + **HTTPS อัตโนมัติ** = กล้องสแกนบาร์โค้ดบนมือถือ/แท็บเล็ตใช้ได้เลยโดยไม่ต้องตั้ง `HTTPS=1`

## 0) สิ่งที่ควรรู้ก่อนเริ่ม

| หัวข้อ | รายละเอียด |
|---|---|
| **ค่าใช้จ่าย** | บัญชีใหม่ได้เครดิตทดลองใช้ฟรี (~$5) → หลังหมดต้องสมัครแผน Hobby $5/เดือน (ระบบเล็กแบบนี้ใช้พอดีๆ ไม่เกิน) |
| **โค้ดที่ใช้ deploy** | branch **`main`** (โค้ดเสถียรที่ merge จาก dev แล้ว) — dev เอาไว้พัฒนาต่อ จะ deploy เมื่อไหร่ค่อย merge |
| **ฐานข้อมูล** | SQLite — ต้อง **ต่อ Volume** (ดิสก์คงที่) ไม่งั้นข้อมูลหายเวลารีสตาร์ท ⚠️ ขั้นตอนที่ 4 สำคัญที่สุด |
| **ลิงค์คงที่ตลอดไหม** | คงที่ตราบใดที่ (1) ไม่ลบโปรเจกต์/service (2) ไม่ลบ Volume — แม้แก้โค้ดแล้ว deploy ใหม่ ลิงค์เดิมก็ใช้ต่อ |
| **ทำจากที่ไหนได้** | ทำจากมือถือ (เน็ตมือถือ) ได้ทุกขั้นตอน — ยังไม่ต้องเปิดคอมบ้านเลยก็ได้ |

## 1) สมัคร Railway และต่อ GitHub

1. เปิด **https://railway.app** → กด **Login** → เลือก **Login with GitHub**
2. อนุญาตให้ Railway เข้าถึง repo: กด **Configure GitHub App** → เลือก **Only select repositories** → ติ๊ง repo **`Shop`** → Save
   (repo เป็น private ได้ — Railway อ่านได้เพราะเราอนุญาตให้เฉพาะ repo นี้)

## 2) สร้างโปรเจกต์ + Deploy จาก GitHub

1. หน้า Dashboard → **New Project** → **Deploy from GitHub repo**
2. เลือก repo **Shop**
3. ตั้งค่า source:
   - **Branch**: `main`  ← สำคัญ (โค้ดเสถียรที่ merge จาก dev แล้ว)
   - (ถ้าไม่มีให้เลือกตอนแรก ให้ Deploy ก่อนแล้วค่อยเปลี่ยน branch ใน Settings → Source → Redeploy)
4. กด **Deploy** — Railway จะ build เองอัตโนมัติ (~3–6 นาที ครั้งแรกนานหน่อย)
   - ระบบรู้จัก `pnpm` + Node 24 จากไฟล์ `.nvmrc` / `package.json` ใน repo แล้ว (เตรียมไว้ให้เรียบร้อย)

> ✅ คำสั่ง build/start กำหนดในไฟล์ `railway.json` ใน repo แล้ว — ไม่ต้องใส่อะไรเพิ่ม

## 3) ตั้งค่า Environment Variables (ทำตอนกำลัง build ได้เลย)

ในหน้า Service → แท็บ **Variables** → เพิ่ม 2 ตัวนี้:

```
SQLITE_DB_PATH=/data/welfare-store.sqlite
SQLITE_BACKUP_DIR=/data/backups
```

- ไม่ต้องตั้ง `PORT` — Railway ใส่ให้เองอัตโนมัติ
- ไม่ต้องตั้ง `HTTPS=1` — Railway ให้ HTTPS ที่ลิงค์อยู่แล้ว (ผลพลอยได้: กล้องสแกนบาร์โค้ดใช้ได้ทันที)
- (ถ้าอยากได้ข้อมูลตัวอย่างสำหรับเทส: เพิ่ม `SEED_DEMO_DATA=1` — ใส่เฉพาะเมื่อยังไม่มีข้อมูล, ระบบข้ามถ้ามีข้อมูลอยู่แล้ว)

## 4) ต่อ Volume (ดิสก์เก็บฐานข้อมูล) — **ห้ามข้าม**

1. หน้า Service → แท็บ **Settings** → หา **Volumes** → **New Volume** (หรือแท็บ Volumes → Create Volume)
2. ตั้งค่า:
   - **Mount path**: `/data`
   - ขนาดเริ่มต้น 1GB ก็พอ (ฐานข้อมูล + ไฟล์สำรอง)
3. กด **Attach** / Create

> เมื่อกดแล้ว service จะ restart หนึ่งครั้ง — ปกติ
>
> ⚠️ **ห้ามกดลบ Volume ภายหลัง** โดยเด็ดขาด = ข้อมูลทั้งหมดหาย (สำรองก่อนเสมอ ดูหัวข้อ 8)

## 5) เปิดลิงค์สาธารณะ

1. Service → **Settings** → **Networking** → **Generate Domain**
2. ได้ลิงค์ `https://ชื่อโปรเจกต์-xxxx.up.railway.app` — นี่คือลิงค์ถาวรของระบบ (จำไว้ใช้ตลอด)
   - อยากได้ชื่อสวยๆ: ตั้ง **Custom domain** ได้ภายหลัง (เช่น `pos.ชื่อโดเมน.com`)

## 6) เปิดใช้งานครั้งแรก

1. เปิดลิงค์ → ระบบ **ลงใหม่ = ว่าง 100%** → จะเข้า **หน้าตั้งค่าครั้งแรก (Setup Wizard)**
2. สร้างบัญชี **ผู้บริหาร** ตามขั้นตอมในหน้านั้น
3. เสร็จแล้วระบบพร้อมใช้ — และได้ **ทดลองใช้เวอร์ชันโปรพลัส 30 วันอัตโนมัติ** (นำเข้า–ส่งออก Excel, สำรอง–กู้คืนอัตโนมัติ ใช้ได้เลย)
   - หมดโควตาทดลองแล้วต้องการต่อ: ใส่รหัสลิขสิทธิ์ที่ ตั้งค่า → เวอร์ชันและลิขสิทธิ์ (เจ้าของระบบออกรหัสเองได้จากเครื่องมือติดตั้งในโซนผู้พัฒนา)

### ใส่ข้อมูลสินค้า 2 ทาง
- **ไฟล์ Excel**: ตั้งค่า → นำเข้าข้อมูล → ใช้เทมเพลต .xlsx ที่ระบบเตรียมไว้ (มีไฟล์ `สินค้านำเข้า-ฉบับแก้ไข.xlsx` ที่เคยเตรียมไว้ก็ใช้ได้)
- **กรอกเอง**: หน้าสต็อก → เพิ่มไอเทม ทีละตัว

## 7) (ขั้นสูง) ย้ายข้อมูลเดิมจากเครื่องบ้านขึ้น Railway

> ✅ **ไม่ต้องอัพเกรด/แปลงฐานข้อมูลเดิมก่อน** — รอบที่ผ่านมา (r75–r80) ไม่มีการเปลี่ยนโครงสร้างตารางเลย และระบบ **migrate อัตโนมัติทุกครั้งที่บูต** (สร้างตารางที่ขาด + เติมคอลัมน์ใหม่ให้ DB เก่า) — เอาไฟล์เดิมขึ้นไปวางได้ทันที

**ก่อนก๊อปจากเครื่องบ้าน:** ปิดโปรแกรมที่ใช้ DB นั้นอยู่ก่อน (Ctrl+C ที่หน้าต่าง `pnpm dev`) แล้วค่อยก๊อป `data\welfare-store.sqlite` — หรือถ้าจะเผื่อสุดๆ ก๊อปไฟล์ `-wal` `-shm` ที่แนบมาด้วย

### ⭐ ทางเลือก 7ค — อัปโหลดผ่านหน้าเว็บ (แนะนำ — ทำจากมือถือได้เลย ไม่ต้องติดตั้งอะไร)
เหมาะที่สุด: deploy ใหม่เสร็จ → เข้า Setup Wizard สร้างบัญชีผู้บริหาร → แล้วดึงข้อมูลเดิมเข้าทันที (ระบบจะตรวจไฟล์ให้ก่อนทุกครั้ง + สำรองไฟล์ป้องกันให้เอง + บันทึกลง Log):
1. เอาไฟล์ `welfare-store.sqlite` จากเครื่องบ้านเข้ามือถือ/แท็บเล็ต (ส่งผ่าน LINE / Google Drive / USB — ชื่อไฟล์เป็น `.sqlite` ตรง ๆ ไม่ต้องเปลี่ยนชื่อ)
2. เปิดลิงค์ Railway → เข้าสู่ระบบด้วยบัญชีผู้บริหาร → เมนู **ตั้งค่า** → หมวด **ระบบและความปลอดภัย** → แท็บ **สำรองข้อมูล**
3. แถว "นำไฟล์ฐานข้อมูลจากเครื่องอื่นเข้าระบบ" → **เลือกไฟล์ .sqlite** → เลือกไฟล์ของร้าน
4. ไฟล์จะถูกตรวจสอบ (SQLite จริง + ตารางของระบบ + integrity) แล้วปรากฏใน "ไฟล์สำรองทั้งหมด"
5. กดปุ่ม **กู้คืน** ของไฟล์นั้น → ยืนยัน → **ข้อมูลทั้งระบบกลับมาเป็นของเดิมครบ** (สมาชิก · สต็อก · บิล · ผู้ใช้และรหัสผ่านเดิมทุกบัญชี) — ล็อกอินด้วยบัญชีเดิมได้เลย
   - หมายเหตุ: กู้คืนแล้วระบบจะสำรองข้อมูลปัจจุบันไว้เป็นไฟล์ป้องกันก่อนเสมอ และบัญชีที่เพิ่งสร้างจาก Setup Wizard จะหายไป (แทนที่ด้วยบัญชีจริงจากไฟล์) — ให้ออกจากระบบแล้วเข้าใหม่ด้วยบัญชีจริง

### ทางเลือก 7ก — วางไฟล์ตรงเลย (ใช้เมื่อมี Railway CLI บนคอม)
เหมาะตอน deploy ใหม่ ยังไม่ได้กรอกข้อมูลอะไรเพิ่ม และเปิดคอมได้:
1. อัปโหลดไฟล์ขึ้น file host ชั่วคราว (เช่น https://tmpfiles.org) → เก็บลิงค์ดาวน์โหลด
2. `railway login` → `railway link` (เลือกโปรเจกต์+service) → `railway ssh`
3. ใน shell รัน:
   ```
   curl -L "<ลิงค์>" -o /data/welfare-store.sqlite
   rm -f /data/welfare-store.sqlite-wal /data/welfare-store.sqlite-shm
   exit
   ```
4. Dashboard → Settings → **Restart** → เปิดลิงค์ใหม่ — ข้อมูลเดิม + บัญชีผู้ใช้เดิมมาครบ ล็อกอินด้วยรหัสเดิมได้เลย

### ทางเลือก 7ข — กู้คืนผ่านหน้าเว็บ (มี audit + สำรองป้องกันให้เอง)
เหมาะถ้าระบบบน Railway มีข้อมูลอยู่แล้วแล้วอยากทับด้วยของเดิม:
1. ที่เครื่องบ้าน — เปลี่ยนชื่อไฟล์ให้ตรงรูปแบบ:
   ```
   welfare-store-20260101T120000Z.sqlite   (ปีเดือนวัน T ชั่วโมงนาทีวินาที Z — ตัวเลขปรับได้)
   ```
2. อัปโหลดขึ้น file host ชั่วคราว → เก็บลิงค์
3. `railway ssh` แล้วรัน:
   ```
   curl -L "<ลิงค์>" -o /data/backups/welfare-store-20260101T120000Z.sqlite
   exit
   ```
4. เปิดแอป → ล็อกอินผู้บริหาร → **ตั้งค่า → สำรองข้อมูล** → เห็นไฟล์ในรายการ → กด **กู้คืน**
   (ใช้ได้เพราะลงใหม่ได้ทดลองโปรพลัส 30 วัน — ระบบสำรองไฟล์ป้องกันไว้ก่อนกู้คืนเสมอ)

> ⚠️ เลือก "แหล่งความจริง" ให้ชัด: การกู้คืน = ข้อมูลทั้งก้อนถูกแทนที่ ถ้าเพิ่มข้อมูลใหม่บน Railway ไปแล้วแล้วกู้คืนของเดิมทับ ของใหม่ที่พิมพ์ระหว่างทางจะหาย — ถ้ายังจะเอา DB เดิมขึ้น ให้ใช้ Railway เป็นแค่ "ลองระบบ" ไปก่อน ยังไม่ต้องกรอกข้อมูลจริง

### ทางเลือก 7ค — เริ่มใหม่ทั้งหมด
ไม่เอาข้อมูลเดิม: เริ่มว่าง → นำเข้าสินค้าจาก Excel (เทมเพลตใน ตั้งค่า → นำเข้าข้อมูล) + ลงทะเบียนสมาชิกใหม่

## 8) สำรองข้อมูล (ทำเป็นนิสัย)

- ในแอป: ตั้งค่า → สำรองข้อมูล → **สำรองเดี๋ยวนี้** แล้วกดดาวน์โหลดไฟล์ `.sqlite` เก็บไว้ที่เครื่อง/Google Drive
- เปิด **สำรองอัตโนมัติ** ได้ในหน้าเดียวกัน (ตั้งรอบรายชั่วโมง/วัน + จำนวนไฟล์ที่เก็บ)
- ไฟล์สำรองอยู่ใน Volume `/data/backups` — **ควรดาวน์โหลดลงเครื่องสำรองอีกชั้น** เผื่ออะไรก็ไม่พ้นคลาวด์

## 9) การอัปเดตโค้ดใหม่ในอนาคต

**Workflow มาตรฐาน (เหมือนที่ทำมาก่อน):**
1. พัฒนาบน branch **`dev`** → push
2. ดึงลงเครื่อง Local (`git pull origin dev`) → ทดสอบจนพอใจ
3. Merge `dev` → `main` → push main
4. Railway ตรวจพบการเปลี่ยนแปลงบน `main` → **deploy ใหม่อัตโนมัติ** (ลิงค์เดิม ข้อมูลไม่หาย — อยู่บน Volume)
- ระหว่าง deploy แอปจะ restart ~20–40 วินาที
- (อัปเดตด่วนเลยไม่อยากรอ merge: เปลี่ยน Service → Settings → Source → branch เป็น `dev` ชั่วคราวก็ได้)

## 10) คำถามที่พบบ่อย

| อาการ | วิธีแก้ |
|---|---|
| Build ล้ม (exit 137) | หน้า Service → Settings → ปรับ Memory ขึ้น (เช่น 2GB) แล้ว redeploy — build ครั้งแรกกิน RAM ช่วงนึง |
| กล้องสแกนบาร์โค้ดไม่เปิด | ลิงค์ Railway เป็น HTTPS อยู่แล้วจึงควรใช้ได้ — ถ้าเจอปัญหาเช็คว่าเปิดจากลิงค์ `https://...up.railway.app` ไม่ใช่ IP ตรง |
| พิมพ์สลิป/ใบเสร็จออกที่ไหน | การพิมพ์เกิดที่เครื่องที่เปิดหน้าเว็บ — **เครื่องหน้าร้านที่ต่อปริ้นเตอร์ ก็เปิดลิงค์นี้แล้วพิมพ์ได้เลย** |
| อยากเปลี่ยน branch deploy | Service → Settings → Source → เปลี่ยน branch — แนะนำ `main` เป็นค่าหลัก (`dev` สำหรับทดสอบด่วน) |
| อยากหยุดจ่ายเงินชั่วคราว | Settings → สั่ง pause service ได้ (ข้อมูลยังอยู่) — หรือย้ายกลับเครื่องบ้านตามคู่มือ `คู่มือลิงค์เทสถาวร-REMOTE-ACCESS.md` แล้วกู้คืนข้อมูลจากไฟล์สำรอง |
| ใครได้ลิงค์ก็เข้าได้ไหม | ใช่ — ตั้งรหัสผู้ใช้ให้แข็งแรง (Setup Wizard และหน้าผู้ใช้) · อยากปิดมิดชิดใช้ Tailscale แทนได้ |

## เทียบกับแผน "คอมบ้านเป็น Server"

| | Railway (คลาวด์) | คอมบ้าน (เมื่อไฟมา) |
|---|---|---|
| พร้อมใช้ | ✅ วันนี้ (ไม่ง้อไฟบ้าน) | ต้องรอไฟ + ตั้ง ngrok/Cloudflare |
| ลิงค์ถาวร | ✅ `xxx.up.railway.app` | ✅ ถ้าใช้ static domain / tunnel |
| ไฟดับ | ✅ ไม่กระทบ | ⚠️ ลิงค์หลุดจนกว่าไฟกลับ (ตั้ง BIOS auto-on ช่วยได้) |
| ค่าใช้จ่าย | $5/เดือน (หลังเครดิตหมด) | ค่าไฟราวเดือนล่ะหลักร้อย (เครื่องค้าง 24 ชม.) |
| ข้อมูล | Volume บนคลาวด์ (สำรองลงเครื่องได้) | อยู่ในเครื่อง คุมเต็มที่ |

**แนะนำ:** ใช้ Railway ไปก่อนตอนนี้ → พอบ้านมีไฟ ถ้าอยากตัดค่ารายเดือน ค่อยตั้งเครื่องบ้านตามคู่มือ REMOTE-ACCESS แล้วกู้คืนข้อมูลจากไฟล์สำรอง (ระบบรับ–ส่งข้อมูลกันได้ทั้งสองทาง)
