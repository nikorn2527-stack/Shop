# รูปแบบข้อความแจ้งเตือน

ใช้รูปแบบตามผลต่อการทำงาน ไม่เลือกตามเมนูที่เปิด

| กรณี | รูปแบบ | การดำเนินการ |
| --- | --- | --- |
| บันทึกสำเร็จหรือข้อมูลทั่วไป | Toast | ไม่ขัดจังหวะการทำงาน |
| ข้อมูลกรอกไม่ครบ/ต้องแก้ก่อนบันทึก | BlockerAlert สีเหลือง + ข้อความใกล้ช่องกรอก | บอกเหตุผลและวิธีแก้ แล้วกลับไปแก้ในฟอร์มเดิม |
| ทำรายการต่อไม่ได้จริง (ระบบไม่ให้ผ่าน) | BlockerAlert สีแดง | แสดงเหตุผลกลางจอ พร้อมปุ่มรับทราบ |
| ต้องตัดสินใจก่อนทำต่อ | Dialog ของระบบ | แสดงผลที่จะเกิดขึ้นและปุ่มที่บอกการกระทำชัดเจน |
| รายการเงินหรือการลบ | หน้าสรุปยืนยันใน Dialog/Modal เดิม | แสดงสมาชิก/รายการ ยอดเงิน และผลก่อนยืนยัน |

สีของ BlockerAlert: เหลือง = ข้อมูลต้องแก้แล้วทำต่อได้ · แดง = ระบบหยุดงานจริง · เขียว/ฟ้า = ข้อมูลที่ต้องเห็นชัด
เหตุการณ์เดียวห้ามแจ้งสองที่ — เช่น ข้อมูลสมัครสมาชิกผิด ให้ขึ้นกล่องกลางจอจุดเดียว ห้ามซ้ำกับ toast มุมขวาบน

## การจัดวาง

- ให้เลื่อนเฉพาะเนื้อหา ปุ่มยกเลิกและยืนยันต้องมองเห็นได้บนจอเตี้ย
- รายการยาวเลื่อนภายในได้ ไม่ดันปุ่มออกนอกจอ
- ใช้ข้อความบอกการกระทำ เช่น กลับไปตรวจสอบ ไม่ใช้ ตกลง เมื่อความหมายกำกวม
- ไม่ใช้สีอย่างเดียวสื่อระดับความสำคัญ ต้องมีหัวข้อและข้อความอธิบาย
- ใช้คอมโพเนนต์เดิม ตรวจผู้ใช้งานร่วมก่อนแก้ และทดสอบเมนูที่ได้รับผลกระทบ

## ผลที่ตรวจแล้ว

ฟอร์มสมัครสมาชิกใช้ Dialog เดิมสำหรับข้อมูลสมาชิกซ้ำ และตรึงปุ่มฟอร์มหลัก
ทดสอบรายชื่อซ้ำ 12 รายการที่ 1366×768, 1139×334 และ 390×844:
ปุ่มตัดสินใจอยู่ในจอ รายชื่อเลื่อนได้ และกลับไปตรวจสอบแล้วค่าที่กรอกยังอยู่

ข้อมูลกรอกไม่ครบ (ชื่อไม่ครบ · บัตรไม่พร้อม · เงินเริ่มต้นผิด) ขึ้นกล่องกลางจอสีเหลืองจุดเดียว
พร้อมเหตุผลและวิธีแก้ ไม่มี toast มุมขวาบนซ้ำ — สคริปต์ตรวจทั้งสองเงื่อนไขไว้แล้ว
สคริปต์: `scripts/registration-alert-review.mjs` ใช้ฐานสำเนาและจำลองผลตรวจสมาชิกซ้ำ

เอกสารนี้เป็นมาตรฐานสำหรับการปรับต่อ ไม่ใช่หลักฐานว่า Popup ทุกเมนูถูกย้ายครบแล้ว
