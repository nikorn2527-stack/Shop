# 2. Task A — ระบบเลือกเครื่องพิมพ์จริงบนคอมพิวเตอร์

## 2.1 ปัญหาปัจจุบัน

ไฟล์ `client/src/components/PrinterPicker.tsx` ปัจจุบันเป็นรายการชื่อรุ่นเครื่องพิมพ์แบบ hardcode เช่น Epson, HP, Brother และ Canon ไม่ใช่รายชื่อที่อ่านจาก Windows จริง

ค่าที่เลือก เช่น:

- `receiptPrinterName`
- `reportPrinterName`
- `cardPrinterName`

ถูกบันทึกเป็นข้อความใน Settings แต่ยังไม่ได้ถูกส่งไปใช้ในขั้นตอนพิมพ์จริง

จุดพิมพ์ปัจจุบันส่วนใหญ่เรียก `window.print()` ซึ่งให้ Browser เป็นผู้เลือก Printer เอง และไม่รับประกันว่าจะใช้ชื่อ Printer ที่ผู้ใช้เลือกไว้ใน Settings

## 2.2 เป้าหมายที่ต้องทำ

สร้างระบบแบบ Local Printer Agent สำหรับเครื่องหน้าร้าน:

```text
Shop Web App
      ↓ HTTP localhost
Local Printer Helper บน Windows
      ↓
Windows Print Spooler / Printer Driver
      ↓
Printer ที่ผู้ใช้เลือก
```

ระบบต้องแยกให้ชัดเจนระหว่าง:

- การดูรายชื่อ Printer จริง
- การเลือก Printer สำหรับเอกสารแต่ละประเภท
- การทดสอบ Printer
- การสั่งพิมพ์จริงไปยัง Printer ที่เลือก
- การใช้ Browser Print Dialog เป็น fallback

## 2.3 งานที่ต้องทำ

### A1 — Local Printer Helper

สร้างหรือกู้คืน `mini-services/printer-helper` ให้เป็น feature ที่อยู่ใน Git และติดตั้งบนคอมพิวเตอร์หน้าร้านได้

ความสามารถขั้นต่ำ:

- Windows: อ่านรายชื่อด้วย PowerShell `Get-Printer`
- ดึงชื่อ Printer, สถานะ, Default Printer และสถานะ Offline/Ready ถ้าระบบปฏิบัติการเปิดเผยข้อมูลได้
- มี endpoint ตรวจสุขภาพ เช่น `GET /`
- มี endpoint รายชื่อ เช่น `GET /printers`
- มี endpoint ทดสอบสั่งพิมพ์ เช่น `POST /printers/test`
- มี endpoint พิมพ์เอกสารจริง เช่น `POST /print`
- จำกัดการรับคำสั่งเฉพาะ localhost หรือกำหนด token/การยืนยันที่เหมาะสม ไม่เปิดให้เครื่องอื่นใน LAN สั่งพิมพ์โดยไม่มีการควบคุม
- มี timeout, error response และ log ที่อ่านได้

> หมายเหตุ: ห้ามถือว่าการอ่านรายชื่อ Printer สำเร็จเท่ากับการสั่งพิมพ์สำเร็จ ต้องทดสอบทั้งสองขั้นตอน

### A2 — PrinterPicker ใหม่

แก้ `PrinterPicker.tsx` ให้:

- ดึงเฉพาะ Printer ที่ติดตั้งจริงจาก Local Printer Helper
- ไม่มีรายการรุ่น Printer แบบ hardcode เป็นตัวเลือกหลัก
- มีปุ่ม `รีเฟรชรายชื่อ`
- แสดงสถานะชัดเจน:
  - เชื่อมต่อ Helper แล้ว
  - ไม่พบ Printer
  - Helper ไม่ทำงาน
  - ไม่สามารถอ่านสถานะ Printer ได้
- แสดงชื่อ Printer จริงตาม Windows โดยไม่เปลี่ยนชื่อให้คลาดเคลื่อน
- หากผู้ใช้เลือก Printer ที่ถูกลบ/Offline ให้เตือนก่อนบันทึกหรือก่อนพิมพ์
- หาก Helper ไม่ทำงาน ห้ามแสดงข้อความเหมือนว่าเลือก Printer จริงได้แล้ว

### A3 — ผูก Printer แยกตามประเภทเอกสาร

ให้ค่าที่ตั้งไว้ถูกนำไปใช้จริง:

| ประเภทเอกสาร | Setting | หน้าที่ควรใช้ |
|---|---|---|
| ใบเสร็จ/สลิป | `receiptPrinterName` | Thermal printer |
| รายงาน | `reportPrinterName` | A4 laser/inkjet |
| บัตรสมาชิก | `cardPrinterName` | เครื่องพิมพ์บัตร/เครื่องพิมพ์ที่กำหนด |

เมื่อสั่งพิมพ์ ระบบต้องส่งชื่อ Printer ที่เลือกไปยัง Helper ไม่ใช่เพียงเรียก `window.print()` โดยไม่สนใจ Setting

### A4 — ปุ่มทดสอบ Printer

เพิ่ม/ปรับปุ่ม `พิมพ์ทดสอบ` ให้:

- เลือกประเภทเอกสารได้ หรือทดสอบตามแถวที่ผู้ใช้เลือก
- แสดงชื่อ Printer เป้าหมายก่อนกดพิมพ์
- ส่งงานไปยัง Printer ที่เลือกจริง
- แจ้งผลสำเร็จ/ล้มเหลวจากผลตอบกลับของ Helper
- หากเลือก Printer ไม่ได้ ให้หยุดและแจ้งสาเหตุ ไม่ควรพิมพ์ไป Default Printer โดยเงียบ ๆ

### A5 — Fallback ที่ต้องระบุให้ชัด

กรณีใช้งานผ่าน Browser และยังไม่ได้ติดตั้ง Helper:

- อนุญาตให้ใช้ Browser Print Dialog ได้เฉพาะเป็น fallback
- ต้องแจ้งผู้ใช้ว่า “ยังไม่ได้พิมพ์ไปยัง Printer ที่ตั้งค่าไว้โดยตรง”
- ห้ามแสดงสถานะว่าเชื่อมต่อ Printer จริงแล้ว
- ห้ามใช้รายการรุ่น Printer แบบ hardcode เพื่อหลอกว่าเป็น Printer ที่ติดตั้งจริง

# 4. Task C — แก้บัตรสมาชิกให้ขนาดและความคมชัดตรงกัน

## 4.1 ปัญหาปัจจุบัน

### C1 — ปุ่มดาวน์โหลดและพิมพ์ทำงานเหมือนกัน

ใน `client/src/components/MemberCardModal.tsx` ทั้งสองปุ่มเรียก `window.print()`:

```ts
const downloadCard = () => { window.print(); };
const printCard = () => { window.print(); };
```

จึงไม่ใช่ “ดาวน์โหลด PDF” กับ “พิมพ์บัตร” คนละกระบวนการ

### C2 — CSS กำหนดความสูงขัดกัน

CSS หลักกำหนดบัตรพิมพ์เป็น 90×55 มม. แต่มี rule ภายหลังที่ตั้ง:

```css
body:has(#member-card) .member-card { height: auto; }
```

ทำให้ความสูงขึ้นกับเนื้อหา และอาจไม่เท่ากับ Preview หรือบัตรใบอื่น

### C3 — ความคมชัดและขนาด Preview กับ Output ไม่ใช่ source เดียวกัน

Preview ใช้ขนาดบนจอประมาณ 360×220px แต่ Print ใช้ 90×55mm และมี CSS override หลายชุด รวมถึง capture host เก่าที่ไม่ได้ใช้งานตาม flow ปัจจุบัน

## 4.2 มาตรฐานที่ต้องล็อก

ให้เลือกมาตรฐานเดียวและประกาศในระบบให้ชัดเจน:

- บัตรประชาชนไทย: 85.60 × 53.98 มม. หรือ
- นามบัตรไทย: 90 × 55 มม.

จากงานเดิมระบบระบุ 90×55 มม. ดังนั้นทีมต้อง **ยืนยันกับผู้ใช้ก่อน final implementation** หากไม่มีคำสั่งเปลี่ยน ให้ใช้ 90×55 มม. เป็นมาตรฐานเดียวทุกจุด

ให้ Preview, PDF, PNG ถ้ามี และ Print ใช้ layout/config กลางเดียวกัน:

ห้ามมี JSX/CSS คนละชุดที่ทำให้พรีวิวกับพิมพ์ต่างกัน

- ตรวจว่าไม่มีเนื้อหาล้นกรอบ

### C4 — ความคมชัด

- ถ้าสร้าง PDF แบบ Raster ต้องกำหนด DPI ให้พอสำหรับพิมพ์บัตร
- ห้ามใช้ screenshot ความละเอียดต่ำเป็นต้นฉบับ
- Barcode/QR ควรสร้างเป็น image/data URL ที่ความละเอียดเหมาะสม หรือ vector หาก library รองรับ
- ต้องทดสอบสแกน Barcode/QR จากบัตรที่พิมพ์จริง
- ตรวจ PDF ด้วยการซูม 200–400% และตรวจการพิมพ์จริง

### C5 — Batch Print

- บัตรหลายใบต้องใช้ขนาดเดียวกันทุกใบ
- แต่ละใบต้องถูกตัดหน้า/จัดวางอย่างถูกต้อง
- ห้ามใบหนึ่งสูงกว่า/ต่ำกว่าอีกใบเพราะชื่อยาวหรือมีข้อมูลเพิ่ม
- พรีวิว Batch ต้องแสดงจำนวนและลำดับใบครบ
